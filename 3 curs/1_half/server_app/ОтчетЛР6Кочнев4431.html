Задание:

  1. Использовать в качестве основы лабораторную работу №4.
  2. Добавить базу данных, модель данных, JPA-репозитории и сервисы. В схеме должно быть не менее двух таблиц и одного внешнего ключа.
  3. Реализовать операции чтения и записи с помощью JPA (Spring Data JPA).

Описание разрабатываемого продукта:

Вариант 14 — «Сдача недвижимости в аренду». Основа работы — веб-приложение лабораторной №4 на Spring Boot с HTTPS, входом через Spring Security, интерфейсом на Thymeleaf и AngularJS, REST API и журналом аудита. В лабораторной №6 данные объектов, пользователей и событий хранятся в базе H2. Структура базы создаётся миграциями Liquibase; доступ к данным выполняется через Spring Data JPA и Hibernate.

Каждая запись о недвижимости связана внешним ключом с пользователем, который её добавил. Пользователь определяется сервером по текущей сессии. При чтении объекта клиент получает логин автора записи в поле ownerLogin. При обновлении объекта связь с автором сохраняется. Интерфейс показывает автора рядом с данными недвижимости.

Модель данных:

USERS — учётные записи для входа. Поля: USER_ID (первичный ключ), LOGIN (уникальный логин), PASS_HASH (BCrypt-хэш пароля).

PROPERTY — объекты аренды. Поля: PROPERTY_ID (первичный ключ), ADDRESS, PROPERTY_TYPE, AREA, ROOMS, MONTHLY_RENT, AVAILABLE, OWNER_USER_ID (внешний ключ).

AUDIT_EVENT — история создания, изменения и удаления. Поля: AUDIT_ID (первичный ключ), ACTOR, ACTION, PROPERTY_ID, OCCURRED_AT.

Связь: PROPERTY.OWNER_USER_ID → USERS.USER_ID (многие объекты — один пользователь).

В журнале аудита PROPERTY_ID хранится как значение без внешнего ключа: история удаления должна сохраняться после удаления объекта.

Код программы:

2. Настройка базы данных (application.properties):

База H2 работает в памяти. После остановки приложения данные сбрасываются; начальные записи заново загружаются из data.sql.

3. Внешний ключ в миграции Liquibase (db.changelog-master.yaml):

- changeSet:
    id: link-property-to-owner
    author: student
    changes:
      - addColumn:
          tableName: property
          columns:
            - column:
                name: owner_user_id
                type: BIGINT
                constraints:
                  nullable: false
      - addForeignKeyConstraint:
          baseTableName: property
          baseColumnNames: owner_user_id
          constraintName: fk_property_owner
          referencedTableName: users
          referencedColumnNames: user_id

4. Отображение связи между JPA-сущностями (PropertyPE.java):

@Entity
@Table(name = "PROPERTY")
public class PropertyPE {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "PROPERTY_ID")
    private Long id;
    // Поля адреса, типа, площади, комнат, цены и доступности
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "OWNER_USER_ID", nullable = false)
    private UserPE owner;
}

Связь @ManyToOne соответствует внешнему ключу в таблице. Доступ к логину пользователя выполняется в сервисе в рамках транзакции, поэтому связь с отложенной загрузкой доступна при формировании DTO.

5. Репозитории Spring Data JPA:

public interface PropertyRepository extends JpaRepository<PropertyPE, Long> {
}

public interface UserRepository extends JpaRepository<UserPE, Long> {
    Optional<UserPE> findByLogin(String login);
}

Методы findAll, findById, save и delete предоставляются JpaRepository. Запрос findByLogin формируется Spring Data JPA по имени метода.

6. Создание объекта и назначение автора записи (PropertyServiceImpl.java):

@Override
@Transactional
public PropertyDTO create(PropertyDTO property) {
    PropertyPE entity = new PropertyPE();
    copyFields(property, entity);
    String login = SecurityContextHolder.getContext()
            .getAuthentication().getName();
    entity.setOwner(userRepository.findByLogin(login)
            .orElseThrow(() -> new ResourceNotFoundException(
                    "Пользователь " + login + " не найден")));
    PropertyPE saved = propertyRepository.save(entity);
    audit("CREATE", saved.getId());
    return toDto(saved);
}

Значение ownerLogin из запроса не используется для назначения автора. Сервис берёт учетную запись из текущей аутентификации и записывает объект и событие аудита в одной транзакции.

7. Чтение, обновление и удаление через JPA (PropertyServiceImpl.java):

public List<PropertyDTO> findAll() {
    return propertyRepository.findAll().stream().map(this::toDto).toList();
}

public PropertyDTO findById(Long id) {
    return toDto(findEntity(id));
}

@Transactional
public PropertyDTO update(Long id, PropertyDTO property) {
    PropertyPE entity = findEntity(id);
    copyFields(property, entity);
    PropertyPE saved = propertyRepository.save(entity);
    audit("UPDATE", saved.getId());
    return toDto(saved);
}

@Transactional
public void delete(Long id) {
    PropertyPE entity = findEntity(id);
    propertyRepository.delete(entity);
    audit("DELETE", id);
}

REST-контроллер предоставляет GET, POST, PUT и DELETE по адресам /api/properties и /api/properties/{id}. Для передачи данных используется DTO, поэтому наружу не возвращаются JPA-сущности и хэш пароля пользователя.
